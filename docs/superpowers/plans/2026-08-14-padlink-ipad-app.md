# Padlink iPad app: the thinnest thing that works

## Goal

An iPad app that pairs with the Mac and drives its cursor and keyboard. Nothing more.
No pinch, no settings screen, no gesture vocabulary beyond one and two fingers.

The success condition is one sentence: **the user drags a finger on the iPad and the
Mac's cursor moves.**

## What already exists

`PadlinkCore` is complete, tested (107 tests), and **verified to compile for iOS** by
building it against `iPhoneSimulator26.5.sdk` for `arm64-apple-ios18.0-simulator`. There
is no `#if os(macOS)` anywhere in it. `Package.swift:6` already declares `.iOS(.v18)`.

So the protocol, the encryption, the pairing format, and the key routing are done. This
plan is only the touch layer, the camera, and the connection lifecycle.

Exact signatures the iPad calls, verified against source:

- `PairingPayload.parse(_ text: String) throws -> PairingPayload`
- `PairingPayload.pairingID`, `.secret`, `.macName`, `.serviceName`
- `TLSPSK(identity: Data, key: Data)` — identity first
- `PadlinkTransport.connectionParameters(psk: TLSPSK) -> NWParameters` — one psk, singular
- `PadlinkConnection(connection: NWConnection)`, `.start()`, `.send(_:)`, `.cancel()`,
  `.incoming`, `.closeReason` — an **actor**, so all of these need `await`
- `ClientMessage.pointerMove(dx: Int16, dy: Int16, dtMicros: UInt16)`
- `ClientMessage.pointerButton(button: PointerButton, isDown: Bool)`
- `ClientMessage.scroll(dx: Int16, dy: Int16)`
- `ClientMessage.keyText(_ text: String)` — **unlabelled**
- `KeyRouter.messages(forCharacter: Character, modifiers: KeyModifiers) -> [ClientMessage]`
- `Padlink.bonjourServiceType`, `Padlink.protocolVersion`

## Traps, each of which would cost a debugging session

**1. `dtMicros` is `UInt16`, so it caps at 65.5 milliseconds.** Nothing in Core clamps
it, because the Mac never had to produce one. A finger that pauses and then moves
produces a longer gap, and `UInt16(gap)` **traps at runtime**, which on iOS means the app
disappears. Every construction of a `pointerMove` must clamp before converting. This is
the single most likely crash in the whole app.

**2. Bonjour browsing fails silently without the right plist keys.** `NSBonjourServices`
must list `_padlink._tcp`, and `NSLocalNetworkUsageDescription` must explain why. Without
them the browser simply reports nothing, with no error, forever.

**3. Local network permission is a one-shot question with a permanent consequence.** If
the user declines, the app can never see the Mac, and it looks broken rather than
blocked. Same trap Accessibility set on the Mac, and it cost real time there. The app
explains itself *before* triggering the prompt, and detects the denied state afterwards.

**4. `PadlinkConnection.incoming` supports exactly one iterator.** A second consumer
splits frames rather than duplicating them. One read loop, owned by one place.

**5. Info.plist is generated by XcodeGen and gitignored.** Every key goes in
`project.yml` under `info.properties`. A hand-written plist gets overwritten.

**6. The iPad sleeps and Wi-Fi drops.** The connection dies and must be re-established
without re-pairing. The stored key survives; the socket does not.

## Task list

Tasks are ordered so something is testable as early as possible. Tasks 1 to 5 are
testable in the **simulator**, which needs no Developer Mode and no cable.

---

### Task 1: iOS target and plist keys

**Files:** `Padlink/project.yml`

Add a `PadlinkPad` target, `platform: iOS`, deployment target 18.0, depending on
`PadlinkCore`. Add a matching unit test target and scheme.

Required under `info.properties`:

```yaml
NSBonjourServices:
  - _padlink._tcp
NSLocalNetworkUsageDescription: >
  Padlink uses your local network to find and connect to your Mac. Without this
  it cannot see your Mac at all.
NSCameraUsageDescription: >
  Padlink uses the camera only to scan the pairing code shown on your Mac.
UISupportedInterfaceOrientations~ipad:
  - UIInterfaceOrientationPortrait
  - UIInterfaceOrientationLandscapeLeft
  - UIInterfaceOrientationLandscapeRight
```

Signing mirrors the Mac target: ad-hoc by default, overridden by the `padlink` script
when `.padlink-team` exists.

**Verify:** `xcodebuild -scheme PadlinkPad -destination 'platform=iOS Simulator,name=iPad Air 11-inch (M4)' build` succeeds.

---

### Task 2: `MoveThrottle` — the clamp that prevents the crash

**Files:** `Padlink/PadlinkPad/MoveThrottle.swift`, plus tests

Pure logic, no UIKit, fully unit tested. Converts a touch delta and a time gap into a
safe `ClientMessage.pointerMove`.

Requirements:

- Clamp the gap to `1...65535` microseconds **before** any `UInt16` conversion.
  A gap of 5 seconds must produce 65535, not a crash.
- Clamp dx and dy to `Int16.min...Int16.max` the same way.
- Return `nil` when both dx and dy round to zero, so the socket is not spammed with
  no-op moves.
- Accumulate sub-pixel remainders rather than discarding them, so slow drags do not
  stall. A 0.4 point move followed by another 0.4 should eventually produce a 1.

**Tests must include:** a gap far beyond `UInt16.max`, a delta beyond `Int16.max`, a
zero move, and an accumulation sequence that crosses the 1-point boundary.

---

### Task 3: `MacBrowser` — find the Mac

**Files:** `Padlink/PadlinkPad/MacBrowser.swift`, plus tests

Core has no Bonjour browser; the only one lives in the test client's executable target,
which cannot be imported. Write one here.

- Wraps `NWBrowser` for `Padlink.bonjourServiceType`.
- Publishes discovered endpoints, matching on service name from the stored pairing.
- Reports a distinct state for "browsing but nothing found", so the UI can say
  "looking for your Mac" rather than appearing frozen.
- **Detects the denied local network permission** and reports it as its own state, not
  as "not found". These need different messages: one is fixable in Settings, the other
  means check the Wi-Fi.

---

### Task 4: `PadPairingStore` — remember the Mac

**Files:** `Padlink/PadlinkPad/PadPairingStore.swift`, plus tests

Conforms to Core's `PairingStore`. Keychain-backed.

Unlike the Mac, iOS **does** support `kSecUseDataProtectionKeychain`, so use it. Use
`kSecAttrAccessibleAfterFirstUnlock` so a paired iPad can reconnect after a restart
without being unlocked first.

---

### Task 5: `PadService` — the connection lifecycle

**Files:** `Padlink/PadlinkPad/PadService.swift`, plus tests

Mirrors the Mac's `PadlinkService`, but as the client.

- Loads the stored pairing, browses, connects, sends `hello`.
- Reads `helloAck` and **surfaces `accessibilityGranted: false` prominently**. This is
  the Mac-side failure that looks like the iPad being broken, and the test client
  already proved how confusing it is without a message.
- One read loop only (trap 4).
- Reconnects when the app returns to the foreground.
- Exposes a simple state: idle, searching, connecting, connected, failed(reason).

---

### Task 6: `TrackpadView` — the actual point of the app

**Files:** `Padlink/PadlinkPad/TrackpadView.swift`

A `UIViewRepresentable` over a plain `UIView` with touch handling. Not SwiftUI gestures:
they add latency and hide the raw timing this needs.

- One finger drag: `pointerMove`, built through `MoveThrottle`.
- Tap: `pointerButton` down then up.
- Tap then immediate drag: button down, moves, button up on release. This is what makes
  text selection work.
- Two finger drag: `scroll`.
- Timestamps come from `UIEvent.timestamp`, not `Date()`, because that is the actual
  moment of the touch rather than the moment the handler ran.

---

### Task 7: Pairing UI and QR scanning

**Files:** `Padlink/PadlinkPad/PairingScreen.swift`, `Padlink/PadlinkPad/QRScanner.swift`

- `AVCaptureSession` with `AVCaptureMetadataOutput`, `.qr` object type.
- **A paste field as well as the camera.** The simulator has no camera, and this is what
  makes Tasks 1 to 6 testable without hardware. It is not a fallback, it is the primary
  path during development.
- Explains the camera permission before requesting it.

---

### Task 8: Main screen and wiring

**Files:** `Padlink/PadlinkPad/PadlinkPadApp.swift`, `Padlink/PadlinkPad/MainScreen.swift`

- Not paired: pairing screen.
- Paired: trackpad, with connection state visible at the top.
- A text field that forwards typing through `KeyRouter.messages(forCharacter:modifiers:)`.
- Local network permission explained on first launch, before the prompt.

---

### Task 9: Simulator verification

Prove the whole path with no hardware: launch in the iPad simulator, paste a pairing
code, drag on the trackpad, watch the Mac's cursor move.

### Task 10: Device verification

Install on the physical iPad. Test what the simulator cannot: real multi-touch, the
camera scanning a real QR code, and behaviour when the iPad sleeps and wakes.
